## 1. nemoa — QRコードメモ共有アプリ

**制作時期：** 専門学校3年生〜現在（個人制作）  
**ディレクトリ：** `nemoa-share-notes/`

### 概要

QRコードで簡単に友達とメモを共有できる iOS / Android 対応のモバイルアプリです。  
高校時代にテスト情報を手軽に共有したいと感じたことがきっかけで開発しました。

### 機能

- メモの作成・編集・削除
- メモ内容をQRコードとして画像生成
- カメラによるQRコードスキャンとメモの読み取り
- 生成したQRコード画像をカメラロールへ保存

### 使用技術

- **React Native (Expo)** — iOS / Android 両対応のクロスプラットフォーム開発
- **TypeScript** — 型安全な実装
- **Expo Router** — ファイルベースルーティングによる直感的なページ管理
- **expo-camera** — カメラアクセスとQRコードスキャン
- **expo-media-library** — 画像のカメラロール保存

### 工夫した点

- オフラインでも動作することにこだわり、サーバーを持たずいつでもメモの作成・共有ができるよう設計した
- iOS・Android それぞれの権限（カメラ・メディアライブラリ）を適切に申請・ハンドリングし、ユーザーへ分かりやすい許可説明文を設定
- Expo Router のファイルベースルーティングを採用し、ページ追加・変更を容易にする構成を意識した
- React Compiler（実験的機能）を採用し、不要な再レンダリングの抑制を検証した

## 2. 六刻巡旅 公式ポータル — ゲーム配布 & コミュニティサイト

**制作時期：** 専門学校3年生・プロジェクト演習3（チーム制作）/ ポートフォリオ公開時に一部改良  
**ディレクトリ：** `rokkoku-junryo-portal/`

### 概要

チームで制作した伝奇ホラーサウンドノベルゲーム「六刻巡旅」の公式ポータルサイトです。  
ゲームの紹介・配布ページと、プレイヤー同士が交流できるコミュニティ掲示板を一から設計・実装しました。

> **備考：** コミュニティ掲示板は PHP / SQLite で動作するため、GitHub Pages のデモではゲームポータルページのみ閲覧可能です。ローカルでの起動方法は `rokkoku-junryo-portal/README.md` に記載しています。

### 機能

- ゲーム紹介ページ（パーティクルエフェクト・クロスフェードスライドショーによる演出）
- ゲームの配布・ダウンロード
- ユーザー登録・ログイン・アカウント管理（編集・削除）
- コミュニティ掲示板（攻略・考察・Q&A の3部屋）
  - 投稿・返信・いいね機能
  - 返信・いいねの通知システム（未読バッジ表示）
  - キーワード検索
- ゲームクリア者向けパスワード認証ボーナスコンテンツ
- 管理者ダッシュボード（ユーザー一覧・アカウント管理）

### 使用技術

- **ゲーム本体：** Unity (C#)
- **フロントエンド：** HTML5 / CSS3 / JavaScript (Vanilla)
- **バックエンド：** PHP
- **データベース：** SQLite
- **テンプレートエンジン：** BladeOne (Composer)
- **コンテナ：** Docker（コミュニティ掲示板のローカル動作確認・デモ用途で使用）

### セキュリティの見直しについて

学校のチーム制作として完成させた段階では、管理者パスワードとボーナスコンテンツのパスワードをソースコード内に直接記述していました。ポートフォリオとして改めて見直した際に問題に気づき、`.env` ファイルで管理する方式に修正しました。`.env` は `.gitignore` に追加し、リポジトリに含まれないよう管理しています。

### 工夫した点

- セキュリティ面として、bcrypt によるパスワードハッシュ化・プリペアドステートメントによる SQL インジェクション対策・`htmlspecialchars` による XSS 対策を実装
- NGワードフィルターを設けて不適切な投稿を自動ブロックし、コミュニティの健全性を担保
- 通知システムを実装し、返信やいいねをリアルタイムに近い形でユーザーへフィードバック
- MVC 構造を採用し、コントローラー・モデル・ビューに責務を分離して保守性を向上
- ゲームのダークホラーな世界観に合わせたUI演出（パーティクルエフェクト・クロスフェードスライドショー）を JavaScript で実装

## 3. ミニアクションシューター

**制作時期：** 専門学校2年生（個人制作）  
**ディレクトリ：** `mini-action-shooter/`

### 概要

HTML5 Canvas と JavaScript のみで実装したブラウザ上で動作する2Dアクションシューティングゲームです。  
外部ライブラリを使わずゲームの仕組みをフルスクラッチで実装することを目標に制作しました。

> **備考：** BGM フォルダは著作権上の理由から音声ファイルを削除しています。

### ゲームフロー

プレイヤーはジャンプしながら、空中に浮かぶ**青い水の球体**を足場にして戦います。敵は絶えず球体を撃ち込んでくるため、それを回避しながら隙をみて射撃で反撃します。青い水の球体に一度乗ると、地上に降りることができなくなります。

### 機能

- キーボードによるキャラクター操作（移動・ジャンプ・射撃）
- 敵キャラクターとの当たり判定
- ゲームオーバー・クリア判定
- BGM・効果音の再生（射撃・ジャンプ・ゲームオーバー・クリア）

### 操作方法

| キー | 操作 |
|------|------|
| A | 左移動 |
| S | 右移動 |
| スペース | ジャンプ |
| Z | 射撃 |
| R | リトライ |

### 使用技術

- **HTML5 Canvas** — ゲーム描画
- **JavaScript (Vanilla)** — ゲームロジック全般

### 工夫した点

- 外部ライブラリを一切使用せず、Canvas API のみで描画・当たり判定・アニメーションループをフルスクラッチ実装
- 状況ごとに効果音を使い分け（ジャンプ・射撃・被弾・クリアなど）、ゲームの手触りを向上

## 4. 数式パズルソルバー

**制作時期：** 専門学校2年生（個人制作）/ ポートフォリオ公開時に一部改良  
**ディレクトリ：** `target-number-solver/`

### 概要

指定した数字群を四則演算で組み合わせて目標値を導く数式を自動で探索するWebツールです。  
パズルゲームの問題を解くために制作しました。

### 機能

- 数字ごとの個別入力ボックスに入力し、目標値を指定すると成立する数式を自動で表示
- ＋ボタンで入力欄を追加、×ボタンで削除
- 解が存在しない場合は「不可能です」と表示
- リセットボタンで入力を一括クリア

### 改良について

当初はカンマ区切りの1つの入力欄で数字を入力する形式でした。利用者が使いやすいよう、数字ごとに個別の入力ボックスを用意する形に改良しました。また演算子を `*` → `×`・`/` → `÷` に変換し、不要な外側の括弧を除去して結果を読みやすく表示するよう改善しました。

### 使用技術

- **HTML / JavaScript (Vanilla)**

### 工夫した点

- 数字の全順列と演算子（+・-・×・÷）の全組み合わせを再帰関数で探索するアルゴリズムを自力実装
- 除算を含む計算における浮動小数点誤差を考慮し、`Math.abs(val - target) < 1e-9` による比較で誤判定を防止

## 5. Photo Reveal — 写真当てアプリ

**制作時期：** 専門学校4年生（個人制作）  
**ディレクトリ：** `photo-reveal/`

### 概要

選んだ写真が粒子から少しずつ形になっていき、早く被写体を当てるほど高得点になるブラウザアプリです。  
HTML5 Canvas と JavaScript のみで制作し、外部ライブラリは使用していません。

### 機能

- 端末内の画像を読み込んで粒子アニメーションに変換（画像はアップロードせずブラウザ内で完結）
- 経過時間に応じたポイント表示（5 Pts → 1 Pts）とプログレスバー・減点タイミングの目盛り表示
- 完成時間の切り替え（5 / 8 / 12 / 20 秒）と再スタート
- スマートフォンでの全画面表示に対応（セーフエリア考慮）

### 使用技術

- **HTML5 Canvas / JavaScript (Vanilla) / CSS**

### 工夫した点

- 粒子の到着順を乱数ではなく R2 低差異列で決定し、途中のどの瞬間でも画面全体に均等に粒子が並ぶようにすることで、序盤から「粗い写真」として読み取れる状態を作った
- 早く確定する粒子ほど遠くから飛来するよう距離を重み付けし、中盤に取り残された粒子が散らばって見えないようにした
- 背面の縮小画像の解像度と不透明度を経過時間に応じて上げ、「ピントが合っていく」表現を実装
- 粒子数の上限（13,000）と `devicePixelRatio` のクランプにより、スマートフォンでも描画負荷を抑えた
